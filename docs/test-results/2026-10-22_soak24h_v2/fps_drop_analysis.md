## 7. สิ่งที่พิสูจน์ไม่ได้จากข้อมูลที่มี (เก็บเพิ่มหลัง soak)

- **ตัวตรวจ `is_night` เสีย** (SATAVG<16 ให้ false positive: ภาพสี 15:39 ก็ขึ้น is_night=1) — ต้องแก้หลัง soak: คำนวณ saturation จาก **ภาพเต็ม** (ไม่ใช่ SATAVG ของ signalstats ที่อาจเพี้ยนกับ IR illuminator) และแยก "แสงน้อย" ออกจาก "ขาวดำ"
- ยังไม่มีค่า exposure/shutter จริงจากกล้อง — ปริมาณแสงต้นทางวัดไม่ได้ตรง (brightness_mean เป็นค่าหลังชดเชยแล้ว); ถ้าได้ควรเก็บ lux/exposure จาก API กล้อง หรือ framerate ที่ negotiate จาก caps RTSP

## 10. ช่วง fps ตกต่อเนื่อง 01:31–06:04 เป็นโหมด IR ไหม?

### 10.1 ข้อจำกัดข้อมูล
`brightness.csv` เก็บแค่ `brightness_mean` (YAVG) กับ `is_night` — **ไม่ได้เก็บ SATAVG ดิบ** (soak_slow.sh คำนวณ SATAVG แล้วทิ้ง เหลือแต่ธง is_night). และ `is_night=1` **ทุกแถว** รวมช่วง 16:05+ ที่ยืนยันว่าเป็นภาพสี ⇒ **is_night และ SATAVG ที่ไฟล์มี ใช้แยกโหมด IR ไม่ได้**

### 10.2 เทียบ 3 ช่วง (จากข้อมูลจริง)

| ช่วง | n (fps/bright) | SATAVG | brightness_mean (avg/min/max) | fps_in avg | saturation จาก snapshot |
|---|---|---|---|---|---|
| A: 01:31–06:04 (fps ตก) | 273 / 21 | ไม่มีในไฟล์ | 83.5 / 39.8 / 101.0 | **14.95** | 01:25 meanS 23.6 = สี (จุดเดียว) |
| B: 16:05→ล่าสุด (ยืนยันสี) | 79 / 7 | ไม่มีในไฟล์ | 94.8 / 94.1 / 95.8 | **28.61** | 16:04/16:06 meanS 25.2/28.0 = สี |

### 10.3 จุดที่ค่ากระโดด เทียบกับ fps
- `brightness_mean` ในช่วง A แกว่งแรง: 01:27≈97 → 01:37–02:27≈40 → 02:37–05:01≈100 แต่ **fps_in นิ่งที่ ~15 ตลอด** ไม่ขยับตามการแกว่งของ brightness
- fps เปลี่ยนจริงจุดเดียว = **16:05 (เปิดไฟ)** 15→28; ไม่มีจุดสลับ SATAVG ให้ดู (ไม่มีคอลัมน์)

### 10.4 สรุปตามจริง: **ข้อมูลไม่พอจะสรุปว่าเป็น IR**
- ไม่มี SATAVG ดิบ, is_night เสีย ⇒ วัดโหมด IR ตรง ๆ จาก brightness.csv ไม่ได้
- หลักฐาน saturation เดียวในช่วงนี้คือ snapshot 01:25/01:27 = **ภาพสี (ไม่ IR)** แต่เป็นจุดเดียว; ช่วง 01:37–06:00 **ไม่มี snapshot** (persons=0) จึงไม่มี saturation มายืนยันทั้งช่วง
- **ข้อค้นพบที่ขัดกับสมมติฐาน "แสงน้อย":** ช่วง A ส่วนใหญ่ (02:37–05:01) brightness_mean ≈100 สว่างพอ ๆ กับช่วง B (≈95) แต่ fps ต่างกันมาก (15 vs 28) ⇒ **brightness_mean อธิบาย night-drop ไม่ได้** กลไกที่ทำ fps ตกช่วง 01:31–06:04 **ยังไม่ทราบแน่ชัด** (อาจเป็น exposure/gain/sub-mode ของกล้องที่ brightness_mean จับไม่ได้)
- สิ่งที่ยืนยันได้มีแค่: **เพิ่มแสงสด 16:05 → fps ขึ้น 15→28** (ข้อ 8); ส่วนสาเหตุ fps ต่ำช่วงกลางดึกยัง **สรุปไม่ได้**

**ข้อควรระวัง:** snapshot ทุกช่วงมี overlay (กรอบ/ข้อความ) เหมือนกัน เทียบกันเองได้ แต่ overlay ดัน saturation ขึ้น จึงห้ามใช้ค่า meanS ตายตัวตัดสินว่า "สี/ขาวดำ"

### 10.5 ต้องเก็บเพิ่มหลัง soak
- log **SATAVG ดิบ** (และ brightness) ลง brightness.csv ไม่ใช่ทิ้งเหลือแต่ is_night
- เก็บเฟรม **ดิบไม่มี overlay** เป็นระยะ เพื่อวัด saturation จริง
- ถ้าได้ ดึง exposure/gain/shutter จาก API กล้อง เพื่ออธิบาย night-drop ที่ brightness ไม่ครอบคลุม
